# Book-index Queue worker: local integration, disabled

This is not a deployed service. The preview config intentionally has a zero D1 ID, absent extractor-service placeholder and three false gates. Do not deploy it unchanged. No production bindings or existing OAuth credentials are embedded.

## Implemented

- Service-binding-only `POST https://book-index.internal/wake` dispatches up to20 durable outbox events; no public Worker route/workers.dev/preview URL.
- Queue message exact `{bookId, action: upsert|remove, contentVersion}`. Current publication version/visibility checked before processing. Persistent consumer receipts prevent repeat extraction after verified completion.
- Upsert service response is **not** proof. The consumer requires current eligible generation, ready extraction receipt and matching FTS manifest receipt in D1 before acknowledging ready.
- Remove deletes generation-fenced search rows in chunks1000, then staging/receipt; further continuations until rows gone. Already withdrawn records are excluded from public consumers immediately by their existing eligibility joins. Durable removed receipt survives hard deletion.
- Processing failures: five attempts, safe-code persisted, then actual DLQ send. No fabricated ready when EXTRACTOR is missing. Fails admin projection only for a queued/expired job; cannot overwrite a concurrently active extractor.
- Pending202 and chunk cleanup are resumable continuations, not parser failures; queue send followed by ack is at-least-once. Duplicate delivery is fenced.
- IndexNow helper called only after verified terminal state, including duplicate terminal deliveries. Pending notification is requeued; permanent failure never downgrades ingestion or triggers extraction again. Both notification flags remain false.
- Six-hour cron starts a durable high-water-mark sweep; minute cron continues500 identities per invocation (configurable1..1000) and dispatches due retries. It scans source books, publication history and orphan outbox identities, restores missing revisions/jobs/history/events, detects visibility/generation mismatches, and requeues abandoned work older than2h. Cursor advances only after page repair; lease expiry allows idempotent replay. A new six-hour tick never resets an unfinished cycle. Nominal100k sweep:200 minute ticks (~3h20m), not a measured cloud guarantee; outages extend completion.

## Required integration / acceptance

1. Apply0036/0037 (and0038 for enabled IndexNow) only to authorized preview D1 after review. Provision preview Queues/DLQ and configure exact preview bindings, not production. No resource creation done here.
2. Add a service binding `BOOK_INDEX_WAKE` from Pages to this worker and matching gated `BOOK_INDEX_QUEUE_ENABLED`. Successful create, owner edit/delete, admin review and central edit handlers now call `_public-book-index-wake.js` after commit via `context.waitUntil`. DB triggers retain events if wake fails; do not use a public fetch URL or copy global credentials. `RETURNING` proves intended mutation rows despite lifecycle-trigger work inflating D1 meta.changes; stale CAS never wakes or removes source files.
3. Implement and deploy a **real compatible extraction service** under EXTRACTOR. Request: POST `/internal/public-book-extract`, JSON exact Queue message. It must target that current book/version; use existing bounded Node extractors and existing gateway/source/lease/verified activation rules. 202 means durable processing continues, 2xx means verify D1 proof. A Workers service binding cannot execute the existing Node worker_threads executor directly. This infrastructure boundary is deliberately not faked.
4. Do not run independent Actions and Queue extraction dispatchers as competing retry authorities. Existing legacy executor still has eight-attempt fallback; align/disable its scheduling before Queue activation. Queue processing envelope stops at five genuine failures. Four retry delays occur before terminal fifth failure;12h configured policy entry has no sixth attempt, per documented attachment ambiguity.
5. Full reconciliation now repairs missing source revisions and generation/visibility mismatches across bounded paginated sweeps. Arbitrary source-byte replacement that bypasses both revision triggers and stored object identity still needs the extractor's source-hash verification; no bulk R2 reading is performed by cron. Active edited BOK requires its pinned-release adapter; original-upload cancellation is not site withdrawal.
6. Test actual preview Queue deliveries, DLQ, extractor service, private/deletion races, cold start, retry latency and all claimed formats. Local tests are not cloud acceptance.
