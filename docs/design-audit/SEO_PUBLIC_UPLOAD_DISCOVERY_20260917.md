# Live public-upload discovery

The previous immutable release listing never incorporated new user_books rows, even though individual public book pages refreshed their metadata. With PUBLIC_BOOK_INDEX_EVENTS_ENABLED, middleware now wraps release listings with a bounded current-public upload projection for browse, new-books, existing numeric-author lists, category lists and related-book lists. Public upload routes also load the SEO release so category/related links are available. New category pages may be backed entirely by live uploads; the category index merges/deduplicates live categories.

Only approved public, undeleted books qualify. Any hidden/deleted canonical/account/submission alias vetoes visibility. Current overrides apply to titles/authors/categories. Two fresh primary snapshots fence a withdrawal during immutable asset reads. No source storage keys, account identifiers or body text are selected. Author affiliation requires the stored central_author_id and a visible central author; matching names never establish identity, and an override that changes the author suppresses the old affiliation. Opaque/custom author identities without an existing public numeric route are deliberately not assigned an invented route.

Uploads occupy a deterministic updated_at/id prefix. A page emits at most100 links and200KB, reads at most two intersecting static page slices plus the first page's counts, and never loads the entire book index. Categories are capped at1000 live and1000 immutable categories; exceeding the bound fails closed rather than declaring partial coverage complete. Static and public-book routes remain distinct.

Counts caveat: upload counts are exact. Existing immutable listing totals precede central visibility filtering; merged results explicitly mark totalExact=false when there is a static component. HTML uses only next/previous navigation, not a claim of an exact visible count. Making immutable visible counts exact requires a materialized membership/visibility count, not an unbounded scan on each request. This pre-existing limitation is not represented as solved.

Verification:11 tests passed across dynamic listing, immutable listing and actual HTMLRewriter suites. Focused tests cover125 uploads+251 catalog books across4 pages without duplication, explicit author association, private/pending/deleted/alias exclusions, edits, new categories, and withdrawal while awaiting an asset. No deployment or cache-latency acceptance is claimed.
