# عداد زوار الخِزانة على Cloudflare Pages

## العقد

- العداد يحصي **المتصفحات الفريدة تقريبًا**، لا الأشخاص: يضع معرّف UUID عشوائيًا في Cookie لمدة سنة.
- الـCookie هي `HttpOnly; Secure; SameSite=Lax`، ولا يقرأها JavaScript.
- لا تُخزَّن عناوين IP أو User-Agent أو البريد أو أي بصمة جهاز.
- الرقم التاريخي المبدئي `500` محفوظ في جدول metadata، وتضاف إليه المعرّفات الفريدة اللاحقة.
- عند غياب D1 أو الجداول أو فساد الناتج تُرجع الوظيفة `503` ويبقى المؤشر مخفيًا؛ لا يعرض التطبيق رقمًا تخمينيًا.
- لا تنشئ الوظيفة مخطط قاعدة البيانات أثناء طلب المستخدم. تطبيق الهجرة خطوة نشر صريحة مستقلة.

## الملفات

- `alpha-publish/migrations/0001_visitor_counter.sql`: الجداول والرقم التاريخي.
- `alpha-publish/functions/api/visitors.js`: `GET` للقراءة و`POST` لتسجيل المتصفح ثم القراءة.
- الربط المطلوب اسمه `VISITORS_DB`.

## التفعيل لاحقًا

بعد إنشاء قاعدة D1 المصرح بها، يُطبَّق ملف الهجرة محليًا ثم عن بُعد، ويُضاف ربط D1 باسم `VISITORS_DB` إلى مشروع Pages للإنتاج والمعاينة. لم تُنشأ قاعدة خارجية ولم يُنفذ نشر ضمن هذه الدفعة.

تعتمد الوظيفة على binding داخل `context.env` وعلى prepared statements وbatch، وفق عقد Pages Functions وD1 الرسميين. طلبات POST العابرة للمواقع تُرفض، والاستجابات كلها `private, no-store`.
