# مصالحة build outbox بعد حفظ مراجعة المصدر — 2026-08-09

## الفجوة المثبتة

تنفيذ D1 يعتمد قيود التفرد وCAS بدل معاملة طويلة عبر التخزين والكائنات. إذا نجح
`createRevision` ثم انقطع التنفيذ أثناء `enqueueBuildForRevision`، تعيد المحاولة
المراجعة الموجودة وتصلح upload/quota، لكنها كانت لا تضمن اكتمال `book_builds`
و`build_jobs`. النتيجة الممكنة: مصدر محفوظ لا يدخل pipeline المشتقات.

## الإصلاح

- مصالحة العملية المكتملة تقرأ المراجعة مقيدةً بثلاثة مفاتيح:
  `revisionId + bookId + operationId`.
- للمراجعة غير المتعارضة تعيد تنفيذ إدراج build والوظائف الخمس باستعمال
  `INSERT OR IGNORE`، فيكتمل أي جزء مفقود بلا ازدواج.
- المراجعة المتعارضة لا تُنشئ لها jobs حتى حسمها، وفق العقد القائم.
- المصالحة تبقى idempotent مع upload/quota/audit.

## التحقق

- اختبار D1 يحاكي مراجعة محفوظة ومصالحة مرتين، ويثبت محاولات الإدراج الآمنة
  للـbuild والوظائف الخمس وربط القراءة بالمفاتيح الثلاثة.
- اختبارات المزامنة الحالية: 325/325 في 79 ملفًا، مع COM اختياري متجاوز.
- فحص TypeScript للحزم الأربع ناجح بعد استقرار التعديل المتزامن.

لا نشر، ولا بيانات مستخدم، ولا تعديل app أو OOXML.
