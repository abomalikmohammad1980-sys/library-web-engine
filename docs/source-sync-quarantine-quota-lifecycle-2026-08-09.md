# دورة حصة الرفع المحجور — 2026-08-09

## الخلل المغلق

كان `finalize` يحرر حجز التخزين عند وضع DOCX في الحجر. إذا سمح المسؤول بالملف
ثم أعاد العميل `finalize`، تُنشأ المراجعة لكن `commitUsage` لا يجد حجزًا، فتفلت
بايتات المصدر من حصة الحساب.

## العقد بعد الإصلاح

- يبقى الحجز `reserved` ما دام قرار الحجر `pending`.
- قرار `allow` يسمح بإكمال المراجعة ثم يحول الحجز مرة واحدة إلى `committed`.
- قرار `reject` يحرر الحجز ولا ينشئ مراجعة.
- قرار `pending` يُرفض قبل `stat/read/SHA-256`، فلا يستطيع تكرار finalize تضخيم
  كلفة قراءة R2 أو التجزئة؛ قرار allow وحده يكمل التحقق الكامل.
- انتهاء الرفع يحرر الحجز عبر المسار الموجود، والصيانة تبقى شبكة أمان للعمليات
  التي لم يعد العميل إليها.
- replay بعد السماح لا يضاعف السعة أو حدث التدقيق.
- نتيجة `reserveUsage=replay` بلا upload قائم تفشل مغلقةً ولا تُنشئ رفعًا غير
  محتسب؛ استعادة الرفع الصحيحة تحدث قبل الحجز من سجل upload المطابق.

## التحقق

- اختبار fault/security يغطي `quarantine → allow → finalize`: الحجز لا يختفي،
  ثم يلتزم مرة واحدة.
- اختبار الرفض يغطي `quarantine → reject`: الحجز يتحرر، ولا committed bytes.
