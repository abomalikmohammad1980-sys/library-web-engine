# `w:sdtContent` وترتيب كتل الخلية

## الفجوة

يعامل المستخرج content controls كحاويات شفافة، وهو صحيح دلاليًا. لكن الاستدعاء
التكراري كان ينشئ عداد `cellBlockIndex` جديدًا داخل `w:sdtContent`. في خلية
مثل `A / SDT(table B, C) / D` كانت كتل SDT تتصادم مع A عند الصفر، ثم يأخذ D
موضعًا لا يعكس ترتيب OOXML.

## الإصلاح

يمرر `flattenBlocks` كائن عداد مشترك عند عبور `w:sdtContent` في الخلية نفسها.
وبذلك تظل الحاوية شفافة بلا فقرة مصطنعة، بينما يستهلك كل `w:p` و`w:tbl`
الداخلي موضعًا من التسلسل نفسه. تبدأ الخلية الجديدة عدادًا جديدًا، وكذلك خلايا
الجدول الابن؛ فلا تختلط فضاءات الترتيب بين المالك والابن.

## الانحدار

يثبت synthetic `A / SDT(table B, C) / D` القيم التالية:

- A عند 0، والجدول B عند `parentBlockIndex=1`، وC عند 2، وD عند 3.
- scene يرصف `A,T1,C,D` رأسيًا داخل خلية واحدة.
- DOM يخرج أبناء td بنصوص `A,B,C,D` بهذا الترتيب.

تبقى اختبارات mixed blocks والجداول الثمانية الرسمية من run34/35 كاملة، ولا
تتغير paragraph identity أو فقرات حقول PAGE المغلفة بـSDT.
