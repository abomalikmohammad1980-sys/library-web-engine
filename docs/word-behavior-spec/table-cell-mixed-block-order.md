# ترتيب كتل الخلية المختلطة

## المشكلة

تسمح خلية Word بتعاقب مباشر مثل `w:p، w:tbl، w:p، w:tbl، w:p`. كانت شريحة
run34 تعرف الخلية الأم لكل جدول، لكنها ترسم الأبناء قبل كل الفقرات؛ وهذا صحيح
للعينة الرسمية المتسلسلة فقط، ولا يحفظ ترتيبًا مختلطًا عامًا.

## العقد

- تحمل كل فقرة خلية `cellBlockIndex` وفق ترتيب أبنائها المباشرين في `w:tc`.
- يحمل الجدول الابن `parentBlockIndex` مع عنوان
  `parentTableId/parentRow/parentCol`.
- تمر القيمة إلى SceneTableSource/Row/Fragment وTableData في DOM، وتظهر أيضًا
  كسمة `data-word-parent-block` لأغراض التشخيص.
- لا يتغير `BodyParagraph.index` أو عدد الفقرات، لذلك تبقى هوية WordPageMap.

## الرسم

يجمع DOM الفقرات والجداول الأبناء في قائمة blocks مرتبة ثم يضيفها إلى `td`.
ويبني scene القائمة نفسها، فيتقدم مؤشر y بالتناوب بين نص وجدول، ويحتسب ارتفاع
كل جدول قبل الفقرة التالية. Canvas/HTML يستفيدان من هندسة scene العودية التي
أغلقتها run34.

## الانحدار

يثبت synthetic `A / table(B) / C / table(D) / E`:

- model: فقرات الأب عند 0 و2 و4، والجدولان عند 1 و3.
- DOM: خمسة أبناء بالترتيب النصي `A,B,C,D,E`.
- scene: المواضع الرأسية مرتبة `A,T1,C,T2,E`.

وتبقى عينة Open XML SDK الرسمية `complex table.docx` ذات العمق الثمانية
انحدارًا مستقلًا، مع حارس العمق 16 والجداول المسطحة الحالية.

حد معروف: كتل `w:sdtContent` المتداخلة داخل الخلية تُعامل حاوية شفافة حاليًا؛
ترتيب أبنائها الداخلي محفوظ، لكن لا تملك الحاوية نفسها block identity مستقلة.
