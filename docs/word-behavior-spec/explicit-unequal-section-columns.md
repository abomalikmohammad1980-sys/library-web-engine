# الأعمدة الصريحة غير المتساوية

## العينة الرسمية والأمان

استُخدمت `columns1.docx` من مستودع `dotnet/Open-XML-SDK` الرسمي، من مسار
اختبارات `wordprocessing/columns`، وحُفظت تحت `tmp/Word external QA` فقط.
SHA-256 هو
`1C09B1299355A063B5EFFA6E30EE6869D181097B4B7ABBA82141C5EA199632C6`.
تضم الحزمة 11 مدخل ZIP، بلا VBA أو OLE أو ActiveX أو embeddings أو ملفات
تنفيذية أو علاقات خارجية.

## مرجع Word والفجوة

أكد Word COM/PDF مستندًا من 19 صفحة و8 مقاطع بهوامش ثابتة. تضم المقاطع
ثلاثة أعمدة متساوية، عمودين متساويين، ثم حالتين غير متساويتين:

- 5399 twip ثم 2487 twip، وبينهما 425 twip.
- 2487 twip ثم 5399 twip، وبينهما 425 twip.

يصرح OOXML بذلك عبر `w:cols w:equalWidth="0"` وأطفال `w:col`. كان النموذج
يقرأ `num/space` فقط ويختلق عرضًا متساويًا، فتُفقد هندسة المصدر.

## السلوك

- يحفظ `SectionGeometry.explicitColumns` عرض كل `w:col` ومسافته التالية،
  بالترتيب المنطقي للمصدر.
- يبقى مسار CSS متعدد الأعمدة للمقاطع المتساوية بلا تغيير.
- لا يستطيع CSS multi-column التعبير عن عرض مختلف لكل عمود مع تدفق تلقائي.
  لذلك يخرج DOM تدفقًا خطيًا محافظًا على النص، ويعلن
  `data-word-unsupported-columns="unequal-widths"` بدل عرض متساوٍ مختلق.
- دعم pagination بصري كامل للأعمدة غير المتساوية مؤجل إلى محرك تدفق يملك
  حدود كل عمود؛ لا تُحوّل البيانات الصريحة إلى تقريب.

## الانحدار

يثبت اختبار العينة الرسمية قيم 5399/2487 واتجاهها المعكوس في المقطع الآخر،
ويثبت اختبار DOM عدم تشغيل `column-count` المتساوي ووجود حالة fallback الصريحة.
