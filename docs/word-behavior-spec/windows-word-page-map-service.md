# خدمة WordPageMap الموثقة على Windows

## الغرض والحدود

هذه خدمة محلية أو داخلية خلف API موثوق لتحويل DOCX (أو أجزاء DOCX) إلى
`WordPageMap` بواسطة Microsoft Word COM. ليست endpoint عامة، ولا يجوز اعتبار
ترقيم المتصفح التقديري بديلاً عنها. لا تصبح النتيجة `authoritative` إلا بعد
اكتمال Word والتحقق البنيوي من الخريطة.

## التشغيل

المدخل التنفيذي هو `khizana-word-map`. يلزم حقن الإعدادات التالية في بيئة
الخادم، ولا توجد قيم سرية ثابتة داخل المصدر:

- `KHIZANA_WORD_MAP_PORT`: منفذ صحيح من 1 إلى 65535.
- `KHIZANA_WORD_MAP_TOKEN`: مفتاح Bearer بطول 32 محرفًا على الأقل.
- `KHIZANA_WORD_MAP_SCRIPT`: المسار المحلي إلى `tools/convert-docx-to-pdf.ps1`.
- اختياريًا: `KHIZANA_WORD_MAP_HOST` (الافتراضي `127.0.0.1`)، والمهلة وحدود
  حجم الجزء/المجموع/عدد الأجزاء ومجلد المؤقتات.

ينبغي أن يبقى الربط على loopback، أو خلف وسيط داخلي يفرض TLS وهوية المستخدم
وحدود الطلب. لا يشمل هذا العقد نشرًا عامًا.

## عقد HTTP

`POST /v1/word-page-map` مع `Authorization: Bearer …` وجسم JSON:

```json
{ "parts": ["<base64 docx>", "<base64 docx>"] }
```

تأتي الاستجابة بـ`schemaVersion=1` و`authoritative=true` و
`engine=microsoft-word-com`، وبصمة SHA-256 للمجموعة ولكل جزء، ثم خريطة كل جزء.
`HEAD` على المسار نفسه فحص جاهزية مصادق. كل الاستجابات `no-store`.

## السلامة والموثوقية

- التنفيذ متسلسل لأن Word COM ليس عامل تحويل متوازيًا آمناً.
- تُرفض التواقيع غير الشبيهة بـDOCX، والجزء الفارغ، وتجاوز العدد أو الحجم قبل
  تشغيل Word.
- لكل طلب مجلد مؤقت مستقل، ويحذف في `finally` عند النجاح والفشل والمهلة.
- يسجل PowerShell رقم عملية WINWORD التي أنشأها الطلب وحدها؛ عند المهلة تُنهى
  شجرة تلك العملية، ولا يُقتل Word مفتوح مسبقًا للمستخدم.
- `starts` تسجل الصفحات التي تبدأ فيها فقرة فقط؛ لذلك قد يقل عددها عن الإجمالي
  عند وجود ورقة فارغة. حين يحدث ذلك يصبح سجل `pages` الكامل إلزاميًا: سجل واحد
  مرتب لكل physical page من 1..N، وتمثل الورقة الفارغة بـ
  `firstParagraphIndex=lastParagraphIndex=-1` ونصين فارغين. لا تُختلق بداية
  فقرة مكررة ولا تُسقط الورقة.
- بوابة التحقق المشتركة بين الخدمة وعميلها ترفض: ترتيب physical/paragraph غير
  المتزايد، حدود الفقرة الخارجة، سجل pages ناقصًا أو مكررًا، نصًا مزعومًا لورقة
  فارغة، أو paragraphs لا تطابق العدد والفهرس والمدى الفيزيائي.
- الأخطاء الخارجية رموز ثابتة فقط: `invalid_request`, `unauthorized`,
  `too_large`, `timeout`, `conversion_failed`. لا تسجل الخدمة مسارات الملفات
  ولا النصوص ولا محتوى DOCX، ولا تعيد تفاصيل الاستثناءات.
- البصمة تربط cache/artifact ببايتات المصدر المحددة؛ أي تعديل في Word ينتج
  بصمة جديدة، فلا يعاد استعمال خريطة قديمة لنسخة معدلة.

## بوابة الإثبات

- synthetic: تحقق البصمة، البنية، التنظيف، المهلة، الحدود، المصادقة والمنفذ
  المحقون، ومنع تسريب المسارات.
- corpus اختياري على جهاز Windows/Word:
  `KHIZANA_WORD_COM_TEST=1 pnpm exec vitest run packages/source-sync-node/src/word-page-map-service.corpus.test.ts`
- النتيجة المرجعية: «منهاج مخيم جيل العزة» = 41 ورقة، و«توحيد الحاكمية» =
  32 ورقة، في طلب متعدد الأجزاء واحد. أعيد تشغيل بوابة Word COM بعد عقد
  الأوراق الفارغة في 2026-08-09 وبقيت النتيجتان 41/32.
- تحقق Word COM مؤقت من نص/كسرين/نص أعاد 3 أوراق وstarts ‏1,2,3؛ أنشأ Word
  فقرة فارغة مالكة للورقة الوسطى. يبقى عقد `-1/-1` للحالة الأندر التي لا يعيد
  فيها COM أي Paragraph للورقة، ولا يغيّر تمثيل الفقرة الفارغة الطبيعي.

## نقطة الربط التالية

ينفذ `WordPageMapPipeline` الربط الداخلي بعد تثبيت source revision:

1. يحسب SHA-256 لكل جزء من البايتات المثبتة ويرسلها إلى العميل الداخلي فقط.
2. يطبق مهلة صلبة وإعادة محاولة محدودة للأخطاء المؤقتة.
3. يرفض الاستجابة إن لم تطابق بصمة وعدد وحجم كل جزء، حتى لو حملت وسم
   `authoritative`.
4. يطلب من مخزن backend في معاملة واحدة مقارنة `sourceRevisionId` وكل بصمات
   الأجزاء الحالية ثم حفظ artifact كاملًا. فشل المقارنة يعني `stale_source`
   ولا يُكتب شيء.

يفرض عميل HTTP رابط HTTPS داخليًا أو HTTP على loopback فقط؛ لا يصل token إلى
المتصفح ولا يوجد route عام proxying للخدمة. عند غياب الخدمة أو فشلها يبقى
القارئ `approximate` ويتيح تنزيل الأصل؛ لا يرفع النتيجة التقديرية إلى موثقة.
